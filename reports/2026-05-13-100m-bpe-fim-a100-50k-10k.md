## Interpretation
This is a large improvement over the 5k-example run:

| Run | Validation Loss | Masked-token Perplexity |
| --- | ---: | ---: |
| 5k examples / 1k steps | 9.7303 | 16,819.36 |
| 50k examples / 10k steps / A100 | 7.1537 | 1,278.88 |

The model is learning meaningful signal: random prediction over a 16,384-token vocabulary has loss `ln(16384) = 9.70`, while this run reached validation loss `7.15`.

The metric is still high. This is a 16k-BPE fill-in-the-middle masked-token perplexity, not standard causal LM perplexity. FIM middle-only denoising is harder and supervises fewer target tokens than full-span masked LM.

## Known Issues
- Training loss is not token-weighted during gradient accumulation. Each microbatch currently contributes equally even when the number of masked tokens differs. Validation is token-weighted, so train/validation loss are not perfectly comparable.
- A100 utilization during the run showed strong compute utilization, about 92-96%, but only about 4GB of 40GB memory used. Larger microbatches may improve throughput.
- The backbone is functional but basic: learned absolute positions, GELU FFN, pre-norm `TransformerEncoder`; no RoPE, RMSNorm, SwiGLU, or FlashAttention yet.

## Next Steps
